---
title: "レート制限とクォータ"
description: "テナント単位のレート制限、日次・月次クォータ、429 レスポンス、正しいバックオフ方法。"
---

レート制限はキー単位ではなく**テナント単位**で適用されます。テナントに属するすべてのキーが同じ枠を共有します。制限は Redis ベースの固定ウィンドウで管理されます。カウンターは毎分の切り替わりでリセットされるため、ある分の終わりに枠を使い切り、次の分の初めに同じだけ送ることが可能です。このパターンを抑えているのが下記のバースト制限です。

## レート制限

| 区分 | デフォルト | 備考 |
| --- | --- | --- |
| 1 分あたり | **300 リクエスト / 分** | テナント単位、固定ウィンドウ |
| バースト | **100 リクエスト / 10 秒** | 分単位の制限に加えて適用 |

Comdesk はこれらの値をテナントごとに調整できます。連携で別の枠が必要な場合は Comdesk にお問い合わせください。

## クォータ

| クォータ | デフォルト | リセット |
| --- | --- | --- |
| 日次リクエスト | **100,000 / 日** | 毎日 0 時（Asia/Tokyo） |
| 月次リクエスト | **2,000,000 / 月** | 毎月 1 日（Asia/Tokyo） |

クォータにカウントされるのは成功したリクエストのみです — `4xx` または `5xx` レスポンスで終わったリクエストは払い戻されます。

## レート制限ヘッダー

成功したすべての v1 レスポンスに含まれます：

| ヘッダー | 意味 |
| --- | --- |
| `X-RateLimit-Limit` | 1 分あたりの許可リクエスト数（例：`300`） |
| `X-RateLimit-Remaining` | 現在の 1 分間の残りリクエスト数 |
| `X-RateLimit-Reset` | 現在の 1 分間のウィンドウがリセットされる Unix タイムスタンプ |

## 上限を超えたとき

`Retry-After` ヘッダー（待機秒数）付きで `429 rate_limit_exceeded` を受け取ります。同じ値が `details.retry_after` にも入ります：

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 30
X-RateLimit-Limit: 300
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1717315200
```

```json
{
  "error": {
    "code": "rate_limit_exceeded",
    "message": "Rate limit exceeded. Please retry after 30 seconds.",
    "details": { "retry_after": 30 }
  }
}
```

バースト制限に達した場合、`Retry-After` は現在の 10 秒ウィンドウの終わりまでを示し、1 分あたりの制限に達した場合は現在の 1 分の終わりまでを示します。テナント管理者にもメールで通知されます（最大 15 分に 1 回）。

日次・月次クォータを使い切った場合は、代わりに `429 quota_exceeded` を受け取ります。`Retry-After` にはクォータがリセットされるまでの時間が設定されます：

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 3600
X-RateLimit-Type: daily
X-Quota-Limit: 100000
X-Quota-Used: 100000
```

```json
{
  "error": {
    "code": "quota_exceeded",
    "message": "Daily quota exceeded. Limit: 100000, used: 100000.",
    "details": { "retry_after": 3600, "type": "daily", "quota": 100000, "used": 100000 }
  }
}
```

レート制限サービス自体が利用できない場合、Comdesk はフェイルクローズで `503 internal_error` を返します。`429` と同様に扱い、時間をおいて再試行してください。
