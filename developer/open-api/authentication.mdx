---
title: "認証"
description: "API キーによる認証、スコープ、ライセンス、IP 許可リスト、ブラウザのオリジン制限を理解します。"
---

Comdesk Open API は、すべてのリクエストを Bearer トークンとして送信される **API キー**で認証します。各キーは、何ができるかを定める一連の**スコープ**を持ち、任意で利用元を制限する IP 許可リストを持ちます。

## Bearer トークン

すべてのリクエストの `Authorization` ヘッダーにキーを送信します：

```text
Authorization: Bearer <API キー>
```

ヘッダーがない、`Bearer ` プレフィックスがない、未知のキー、無効化されたキーの場合は、いずれも `401 invalid_api_key` を受け取ります。

## API キーの形式

すべてのキーは `cdsk_` で始まり、その後に 45 文字のランダムな文字列が続きます（合計 50 文字）。本番／テストの区別は**ありません** — すべてのキーはテナントの実データに対して動作します。

キーは **設定 → Open API → API キー** で発行します。平文の値は**作成時に一度だけ**表示されます。Comdesk は SHA-256 ハッシュと、識別用の先頭 12 文字のみを保存します。

<Warning>
  キーを紛失すると復元できません。新しいキーを作成してローテーションしてください。
</Warning>

キーは個々のスタッフではなく**テナント**に属し、付与されたスコープの範囲内でテナントレベルで動作します。システムごとにキーを分けて発行すれば、いずれか 1 つを個別に失効できます。

## ライセンス

すべての v1 エンドポイントは、テナントが `open_api` ライセンスを保有している必要があります。Webhook とレポート API には、さらに `open_api_advanced` が必要です。必要なライセンスを持たないテナントは `403 license_required` を受け取ります。

## スコープ

キーには必要なスコープのみを付与します（最小権限）。キーのスコープ外のエンドポイントを呼ぶと `403 insufficient_scope` を受け取ります。

| スコープ | 付与する権限 | エンドポイント |
| --- | --- | --- |
| `calls:read` | 通話履歴の読み取り | `GET /calls`, `GET /calls/{callId}` |
| `customers:read` | 顧客データの読み取り | `GET /customers`, `GET /customers/{customerId}` |
| `customers:write` | 顧客の作成・更新 | `POST /customers`, `POST /customers/bulk`, `GET /customers/bulk/{batchId}`, `PUT /customers/{customerId}` |
| `reports:read` | 統計の読み取り | `GET /reports/*` |
| `webhooks:manage` | Webhook 設定の管理 | `/webhooks/*` |
| `calls:initiate` | 発信の開始 | 予約済み — 現在のリリースにエンドポイントなし（フェーズ 2） |

<Note>
  BI 連携には `reports:read` のみ、リードインポートのジョブには `customers:write` のみで十分です。キーごとに最小限のスコープを付与してください。
</Note>

## IP 許可リスト（任意）

各キーは、最大 **10** 個の送信元アドレスに制限できます。エントリには IPv4・IPv6 アドレス、または IPv4 の CIDR レンジ（例：`203.0.113.0/24`）を指定できます — IPv6 の CIDR レンジには対応していません。設定すると、それ以外の IP からのリクエストは `403 ip_not_allowed` を受け取ります。無制限にする場合は空のままにします。

## ブラウザのオリジン（CORS）

ブラウザから送信されるリクエストには `Origin` ヘッダーが付きます。クロスオリジンのリクエストは、テナント管理者が登録したオリジンからのみ受け付けられ、それ以外のオリジンは `403 origin_not_allowed` を受け取ります。サーバー間のリクエスト（`Origin` ヘッダーなし）は影響を受けません。

## キーの有効期限とローテーション

キーには任意で有効期限を設定して発行できます。期限を過ぎると、リクエストは `401 expired_api_key` を受け取ります。Comdesk はキーの有効期限の **30 日前**にテナント管理者へメールで通知します。

キーは 6〜12 か月ごとにローテーションしてください：

<Steps>
  <Step title="新しいキーを作成する">
    同じスコープで新しいキーを発行します。古いキーはまだ無効化しません。
  </Step>
  <Step title="システムを更新する">
    連携の設定／シークレットストアのキーを差し替えます。
  </Step>
  <Step title="検証する">
    新しいキーでテストリクエストを 1 回送信し、`200` を確認します。
  </Step>
  <Step title="古いキーを無効化する">
    検証後、API キー管理画面で古いキーを無効化します。
  </Step>
</Steps>

## エラー

| ステータス | コード | 原因 |
| --- | --- | --- |
| 401 | `invalid_api_key` | キーが欠落・不正・未知・無効化済み |
| 401 | `expired_api_key` | キーが有効期限切れ |
| 403 | `license_required` | テナントがエンドポイントに必要なライセンスを持っていない |
| 403 | `insufficient_scope` | キーに必要なスコープがない |
| 403 | `ip_not_allowed` | 送信元 IP がキーの許可リストにない |
| 403 | `origin_not_allowed` | ブラウザの `Origin` がテナントに登録されていない |

完全な一覧とエラーエンベロープは [エラー](/developer/open-api/file-3) を参照してください。
